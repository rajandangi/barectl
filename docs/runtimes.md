# Target runtime profiles and PHP masters

This page describes the current integration implementation, including its shared serving masters. The accepted replacement in [ADR 0038](adr/0038-drain-site-php-through-private-haproxy.md) uses per-site HAProxy admission and independent FPM masters per site and runtime. That replacement is not implemented or qualified yet. Existing diagnostic protection evidence does not qualify the new serving convention.

On a verified target-stack host, open **Stack → Runtime catalog** and choose **Add runtime** for `php84`, `php85`, `nodejs_22` or `nodejs_24`. Preparation is read-only. The review names the architecture, exact locked store path, shared effects, configuration and native postconditions. An Administrator applies its Shared review. A Site operator can prepare it but cannot apply a Shared change.

Preparation stores one immutable, versioned, non-secret catalog selection. The worker validates it before SSH. Native apply consumes the stored review, rechecks the touched native evidence under the shared mutation lock, and queries the signed cache before creating a profile or configuration. Nix has `max-jobs = 0` and `fallback = false`; a missing closure refuses rather than compiling. Node creates only `/nix/var/nix/profiles/barectl/<entry>` and starts no service.

A PHP profile selects one locked build. `/etc/php-fpm/<entry>/php.ini`, `php-fpm.conf` and `pools/diagnostic.conf` configure its `php-fpm@<entry>.service` master. The template follows the [pinned NixOS FPM module](https://github.com/NixOS/nixpkgs/blob/7c8764b7c7b09b34f632464276218ef9090eaa11/nixos/modules/services/web-servers/phpfpm/default.nix), using `Type=notify`, the profile executable, explicit ini/configuration, private temporary and device namespaces and `USR2` pool reload. It preserves the Nix wrapper's extension scan configuration by leaving `PHP_INI_SCAN_DIR` unset. A catalog build change requires a restart and is a later reviewed operation.

The master enables OPcache permission and root checks, restricts its API to `/etc/php-fpm/diagnostics/`, disables file cache and preload, and turns off `expose_php`. Passive discovery refuses unexpected diagnostic pool directives and files before executing its fixed probe. Each command has a time limit and its captured output is capped while it runs. A fixed diagnostic script returns only selected effective settings, OPcache directives, PHP version and loaded extensions. Barectl binds the active unit invocation and main executable to the catalog build's wrapped executable and binds the diagnostic worker's actual parent PID to that master. The native unit's MainPID and invocation must remain the same across the request. It executes through that running master's private pool, using the [official pinned fcgi 2.4.7 client](https://github.com/NixOS/nixpkgs/blob/7c8764b7c7b09b34f632464276218ef9090eaa11/pkgs/by-name/fc/fcgi/package.nix) with connect-only mode. Barectl does not implement FastCGI framing.

Before making a diagnostic request, discovery also requires native load evidence. The manager's initial `ExecMainStartTimestamp`, or the successful fixed `ExecReload` command's start timestamp, must follow every guarded configuration file's ctime and mtime. The manager's effective `ExecStart` arguments must select the exact profile executable and standard ini/master paths, with empty unit environment, environment-file, pass/unset-environment and drop-in sources; safe unit bytes on disk alone cannot attest cached manager settings. Current-master syslog datagrams must show the matching complete startup or reload sequence, with trusted PID, executable, boot and invocation fields. Discovery holds the native mutation lock and compares the load and file evidence before and after the request. A disk repair without reload, missing or bounded-out journal evidence, an unbound direct `USR2`, or an observed realtime/monotonic clock discrepancy makes the live evidence unavailable. Ordinary `systemctl reload php-fpm@<entry>.service` establishes a newer configuration-load boundary while the original executed-command binding remains available. A systemd manager reset such as `daemon-reload` clears that per-command PID/start tuple, even if the displayed arguments are unchanged; a service reload cannot restore it. Use ordinary `systemctl restart php-fpm@<entry>.service` to restore verified execution evidence after that reset. Adding another runtime avoids a manager reload when the shared template bytes are unchanged. Discovery never reloads or restarts a service itself.

This is a conservative inference from ordinary native configuration and trustworthy server clocks. It does not attest historical state against root changing clocks or filesystem metadata. PHP request overrides cannot prove the original loaded configuration: FPM can retain pool settings and cached ini `PATH` sections after safe disk bytes are restored. The [locked PHP8.4 FPM request handling](https://github.com/php/php-src/blob/php-8.4.26/sapi/fpm/fpm/fpm_main.c), [PHP8.5 ini activation](https://github.com/php/php-src/blob/php-8.5.11/main/php_ini.c), and [systemd259 execution properties](https://github.com/systemd/systemd/blob/v259/src/core/dbus-execute.c) and [service serialization](https://github.com/systemd/systemd/blob/v259/src/core/service.c) define this boundary. No diagnostic request overrides mandatory OPcache values.

The diagnostic worker runs as the unprivileged locked `php-probe` identity. Its root-owned socket is mode `0600`. The script and every ancestor are controlled by root; only the diagnostic group may read its directory. The pool sets `pm = ondemand`, `pm.max_children = 1` and `pm.process_idle_timeout = 10s`, with private session, upload and temporary directories. It does not override the master's OPcache protections. Site pools must likewise use separate private directories. See [PHP FPM configuration](https://www.php.net/manual/en/install.fpm.configuration.php) and [OPcache configuration](https://www.php.net/manual/en/opcache.configuration.php).

**Stack → PHP runtimes** reads the current discovery snapshot, including native profile generations, exact catalog identity, extensions, master state and live protections. An unknown profile path is reported without adoption. A protection fault blocks changes to that master's pools. It does not block adding an independent PHP master or a Node profile when the selected resource and shared identity/files remain safe; unchanged shared probe and unit files are not rewritten. Missing, inaccessible or malformed evidence is unavailable evidence, never a passing protection. A repeated Add runtime review proposes no changes only when the exact offered build and its live master convention match.

This slice does not qualify cross-site isolation or minimum host capacity. Those require the Phase A native isolation and constrained-host measurements. The host foundation's 4 GiB disk and 900 MiB memory admission thresholds remain provisional.


The executable check follows the pinned [PHP extension wrapper](https://github.com/NixOS/nixpkgs/blob/7c8764b7c7b09b34f632464276218ef9090eaa11/pkgs/development/interpreters/php/generic.nix): the catalog output wraps FPM to preserve extension loading. Barectl compares the running executable with the resolved `.php-fpm-wrapped` inside that exact output, not the wrapper's configured `ExecStart` text alone. A restart during the diagnostic read makes that evidence unavailable.

## Server command defaults

Stack's Defaults section prepares separate Shared reviews for PHP and Node. The [server-default convention](runtime-defaults.md) owns command links, selected-interpreter wrappers, native refusal rules and reconstruction. Existing sites keep their own selections. New-site forms preselect only a fresh, verified observed PHP default.

## Site Node selection

A site's Runtime page offers its own installed Node selection through a Site review. This changes only the root-owned `bin/node`, `bin/npm` and `bin/npx` links under that site to the selected profile. It does not reload PHP or Caddy, change the site's PHP wrappers, change application files, or change server defaults. The native payload rechecks site evidence, profile identity and all link preimages under the existing native and site locks. Native discovery reconstructs the selected profile from all three links. Foreign commands refuse adoption. A mixed or incomplete known-link selection is reported as interrupted and can be repaired through another Node selection review.

PHP runtime switching remains separate. [ADR 0038](adr/0038-drain-site-php-through-private-haproxy.md) replaces the failed direct Caddy route-flip/source-pool removal sequence with single-thread HAProxy maintenance/removability evidence with retained static backend objects and complete native FPM worker drain evidence. Implementation and full qualification remain tracked in [#339](https://github.com/rajandangi/barectl/issues/339); the Node and default actions do not qualify that PHP switch.
