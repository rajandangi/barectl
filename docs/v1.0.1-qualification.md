# v1.0.1 release qualification

Status: release preparation. No v1.0.1 tag or published release exists yet.

## Scope and revision

The application candidate is `eb39e6177a06d40ed0faf70910dc6210ae2985f5`, the committed
`main` revision used to prepare this patch. It includes the dashboard changes in the
[Unreleased changelog](../CHANGELOG.md#unreleased) and the runtime catalog refresh in
[PR #546](https://github.com/rajandangi/barectl/pull/546). The release preparation changes
only version metadata, the transcript audit and release documentation.

Uncommitted changes in another checkout are excluded. This candidate adds the controller
migration `operations.0008_check_progress` after v1.0.0 and keeps native contract version 1.
The migration adds connection-check progress fields with defaults for existing records.
Installing the controller does not apply catalog updates to managed servers.

### Initial failures and retries

The full local build, `run-NibZ0teg`, did not pass as one uninterrupted run:

- The fast gate initially selected macOS LibreSSL 3.3.6, which lacks the
  `openssl verify -verify_hostname` option required by the mirror test. Selecting the
  installed OpenSSL 3.5.9 on `PATH` made all four `MirrorLeafCoherenceTests` pass and then
  the complete fast gate pass. No test or application code changed.
- Docker could not bind a localhost forwarding port while starting a native lane.
  The original native dispatch passed 77 of 91 groups in 295 s and explicitly named the
  14 unfinished groups. A separate four-lane dispatch ran those 14 groups after acquiring
  the shared native lock; all passed in 26 s. No required scenario was removed or weakened.
- The combined build took 343 s, exceeding its 300 s target while staying within the
  900 s hard limit. This timing miss remains recorded; the successful individual gates
  do not turn the interrupted combined build into a pass.

Hosted required checks must pass on the exact release commit before tagging and
publication, as required by the [release procedure](agents/orchestration.md#release).
The draft PR checks validate this preparation; final release documentation and its exact
commit still need that gate before publication.

## Upgrade and limitations

Use the [upgrade procedure](upgrade.md) after publication. Keep the same controller-local
database, saved connections and SSH credentials. The v0.4.x upgrade proof remains part of
the test suite; v0.3.x and earlier still require a fresh installation.

The [1.0 qualification limits](v1.0-qualification.md#not-qualified) still apply. This patch
does not qualify real small hosts, additional reboot or power-loss boundaries, or new
hosting stacks. Journald retention controls remain planned for 1.1.
