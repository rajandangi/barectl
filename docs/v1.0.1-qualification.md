Release date: 2026-11-13. [Release PR #547](https://github.com/rajandangi/barectl/pull/547)
contains the final checked release commit; the annotated `v1.0.1` tag names that commit.

## Scope and revision

The application candidate is `8b8e44078932a9476044faed5b71d84a2b97d94e`, which combines
the original patch preparation with both local commits: responsive server details at
`a904d890` and shared development setup at `ede5797b`. It includes the dashboard changes
in the [1.0.1 changelog](../CHANGELOG.md#101---2026-11-13) and the runtime catalog refresh
in [PR #546](https://github.com/rajandangi/barectl/pull/546). Later release commits update
documentation and qualification evidence.

Both local work commits are included. This candidate adds the controller migration

The migration adds connection-check progress fields with defaults for existing records.
Installing the controller does not apply catalog updates to managed servers.

### Initial failures and retries

The full local build, `run-NibZ0teg`, did not pass as one uninterrupted run:

- The fast gate initially selected macOS LibreSSL 3.3.6, which lacks the
  `openssl verify -verify_hostname` option required by the mirror test. Selecting the
  installed OpenSSL 3.5.9 on `PATH` made all four `MirrorLeafCoherenceTests` pass and then
  the complete fast gate pass. No test or application code changed.
- Docker could not bind a localhost forwarding port while starting a native lane.
  The original native dispatch passed 77 of 91 groups in 295 s and explicitly named the
  14 unfinished groups. A separate four-lane dispatch ran those 14 groups after acquiring
  the shared native lock; all passed in 26 s. No required scenario was removed or weakened.
- The combined build took 343 s, exceeding its 300 s target while staying within the
  900 s hard limit. This timing miss remains recorded; the successful individual gates
  do not turn the interrupted combined build into a pass.

Hosted required checks must pass on the exact release commit before tagging and
publication, as required by the [release procedure](agents/orchestration.md#release).
The initial preparation's hosted checks passed at `ba981115`, including all 11 native
shards. These results are retained for comparison; the combined release must pass the
same required checks on its final commit.

### First combined build

The combined candidate at `ca6333d2` ran the full local build as `run-1P7btzFA`.
The fast gate passed 2,705 tests in 31.650 s with one existing skip, all six validator
groups passed in 43 s, and all 91 native lifecycle groups passed in 309 s. The native
dispatch exceeded its 300 s target; the complete build took 355 s.

The browser stage started before the combined frontend assets were rebuilt. It reported
11 failures from mismatched asset URLs. That browser result is invalid for qualification;
the rebuilt layout's four focused browser tests then passed in 6.738 s. The clean combined
build above used assets prepared before the run and the documented
`BARECTL_NATIVE_LANES=8` setting to reduce contention on the same host. No scenario,
assertion or budget is removed or relaxed.

Independent Standards review found no must-fix or judgement findings. Spec review found
one must-fix in the controller rollback instructions: the restored database must be paired
with the pre-upgrade code revision. The upgrade guide now records that revision before
checkout and restores it with the matching database backup.

## Upgrade and limitations

Use the [upgrade procedure](upgrade.md). Keep the same controller-local
database, saved connections and SSH credentials. The v0.4.x upgrade proof remains part of
the test suite; v0.3.x and earlier still require a fresh installation.

The [1.0 qualification limits](v1.0-qualification.md#not-qualified) still apply. This patch
does not qualify real small hosts, additional reboot or power-loss boundaries, or new
hosting stacks. Journald retention controls remain planned for 1.1.
