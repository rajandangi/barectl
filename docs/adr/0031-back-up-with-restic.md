# Back up with restic

Accepted on 2026-10-10 for [#323](https://github.com/rajandangi/barectl/issues/323), subject to Phase D qualification; not implemented. Supersedes [ADR 0021](0021-use-one-native-rclone-backup-convention.md) and [ADR 0025](0025-delete-expired-backups-by-exact-native-cleanup.md). [ADR 0022](0022-review-destructive-restore-and-coordinated-capture.md)'s restore review and coordinated capture still apply.

Backups use restic repositories: one onsite, optionally one S3-compatible offsite (Amazon S3, Cloudflare R2) receiving copied snapshots. restic supplies encryption, deduplication, retention and restore, which the rclone design would have rebuilt around archive files. restic comes from the pinned Nix catalog, because Ubuntu 24.04's 0.16.4 lacks streamed command input for database dumps and the official static binary would need a Barectl downloader.

ADR 0025 rejected a restic-style repository because it could not express "keep the newest verified copy per scope and location". `forget` with per-scope grouping, `--keep-last 1` and `--keep-within`, preceded by `check` on the same repository, is expected to express it. `check` verifies the repository rather than each snapshot, and a forged recent snapshot could push a real one out of `--keep-last`, so native tests must show the rule holds before retention is enabled. restic's locks coordinate only restic processes, so every backup, copy, forget and prune is a native unit under Barectl's shared lock, with one maintenance actor per repository. Pruning credentials stay separate from capture credentials where the provider allows. R2 does not implement S3 Object Lock, so immutability is configured per provider and never implied. Details are in the [target architecture](../target-architecture.md#backups).
