# Drain site PHP through private HAProxy admission

Accepted on 2026-10-15 for [#339](https://github.com/rajandangi/barectl/issues/339#issuecomment-6182119442), amending [#325](https://github.com/rajandangi/barectl/issues/325). This replaces the shared-serving portions of [ADR 0029](0029-share-one-php-fpm-master-per-runtime.md) and direct Caddy-to-FPM routing in [ADR 0027](0027-serve-sites-and-https-with-caddy.md). It is an accepted implementation direction, not delivered qualification. The unreleased integration still uses the earlier shared serving masters until this replacement lands.

Caddy retains public HTTP, static serving and future HTTPS. Each site has one private ordinary foreground HAProxy process and independent PHP-FPM serving masters keyed by site and runtime, temporarily two during a switch. Sites share immutable runtime builds but do not share serving masters or OPcache. HAProxy comes from the existing exact [nixpkgs revision](https://github.com/NixOS/nixpkgs/tree/7c8764b7c7b09b34f632464276218ef9090eaa11), which supplies 3.3.11. Both supported PHP backend objects remain statically declared, with explicit native IDs, fixed sockets, finite connection limits and disabled defaults. FastCGI keepalive is disabled. The proxy explicitly sets `nbthread 1`, has no daemon or master-worker mode and has no `ExecReload`. PHP switching does not reload Caddy or HAProxy. Creating a site starts its independent HAProxy and FPM services, then publishes its Caddy site file through the existing whole-tree validation, guarded reload and rollback contract. It does not reload other sites' HAProxy or FPM services. Caddy publication still derives Shared consent when its effects are shared. Native unit, process, listener and API peer evidence must establish the single serving generation and complete backend inventory. Site users cannot directly reach application FPM sockets or the administrative API.

A switch verifies and enables target FPM, enables target admission and places source in maintenance. It atomically persists the unedited native `show servers state` output through HAProxy's `server-state-file`, with an immutable base configuration, before source cleanup. A crash before publication keeps both FPM services available and the previous persisted selection. Both static backend objects remain present during switching and after source FPM stops; the inactive source stays in maintenance. No dynamic deletion or re-add is used. Exact repeated selection and restart restoration remain subject to native qualification.

Source cleanup requires the supported `wait srv-removable` predicate in the authenticated proxy process, followed by complete native status and PID evidence that every source application worker is Idle. The wait callback does not take full thread isolation. The explicit single-thread convention prevents CLI callback interleaving with the synchronous backend selection-to-reservation path. Force persistence, health or agent checks, extra backend aliases and alternate direct application access are outside the supported convention. Process identity, complete inventory and maintenance state must remain verified across this boundary. Work after `fastcgi_finish_request()` remains protected by the subsequent FPM drain. A sampled zero counter, fixed sleep, forced session closure or ambiguous POST replay is not a drain boundary. Missing evidence or a bounded operation that cannot drain retains source and reports an incomplete transition. A fresh review may finish or revert; rollback after target admission uses the full reverse drain protocol. A removable predicate alone does not prove earlier requests succeeded, and a process crash cannot be reported as a request-preserving completion.

The existing pyinfra SSH boundary, detached native change engine, global mutation lock and stable site deployment lock remain. Ordinary configuration, running API state, native unit identity and both FPM services reconstruct incomplete transitions from a fresh controller. No custom phase file, inventory manifest, boot repair agent or server-side audit database is added. A switch takes Site consent when all effects are confined to that site; genuine shared effects still require Shared consent. Mandatory OPcache protections and private directories remain. Per-runtime diagnostic-only masters may remain to verify installed builds, loaded extensions and protections for Add runtime. They never serve site pools. Site masters reuse the fixed unprivileged diagnostic and loaded-protection guard bound to their own identity, with private independent application status for drain evidence.

The earlier Caddy route flip followed by source pool removal returned 502 for accepted delayed-body and queued requests in both directions. Retaining the pool passed controls but would leave the switch incomplete. Stable-socket FPM binary re-execution retained the listener yet returned ten 502 responses in a clean twelve-request comparison whose no-reload control passed all requests. Deleting and dynamically re-adding the source backend was also rejected. The live reverse selection worked, but re-add lost the static configuration maintenance flags and restart restored both servers disabled, producing 503. Retaining both static objects preserves the native state baseline without hand-editing state. Public Nginx and graceful old-worker exit remain an alternative, but would replace Caddy and its accepted HTTPS ownership. HAProxy supplies the missing admission primitive while retaining Caddy, at the cost of another process per site and additional memory that must be measured.

Exact selected-build feasibility on arm64 passed both directions with Caddy 2.11.7, HAProxy 3.3.11 and PHP 8.4.26/8.5.11, covering active POSTs, measured FPM and proxy queues, a delayed request body, guarded deletion and exactly-once effects. Separate native FPM status tests showed post-response work as Finishing until application and shutdown completion, then Idle. These experiments do not qualify production units, socket security, integrated post-response drain, file/runtime crash recovery, reverse rollback, multi-site memory or amd64. Those and full local/hosted acceptance remain required. No minimum host size is established.

Version-matched upstream contracts are the [HAProxy 3.3 Runtime API](https://docs.haproxy.org/3.3/management.html), [FastCGI configuration](https://docs.haproxy.org/3.3/configuration.html#10) and [3.3.11 source](https://www.haproxy.org/download/3.3/src/haproxy-3.3.11.tar.gz), [PHP 8.4 request states](https://github.com/php/php-src/blob/php-8.4.26/sapi/fpm/fpm/fpm_request.c), [PHP 8.5 request states](https://github.com/php/php-src/blob/php-8.5.11/sapi/fpm/fpm/fpm_request.c), [FPM process lifecycle](https://github.com/php/php-src/blob/php-8.4.26/sapi/fpm/fpm/fpm_process_ctl.c) and [native status configuration](https://www.php.net/manual/en/install.fpm.configuration.php). The [owning issue amendment](https://github.com/rajandangi/barectl/issues/339#issuecomment-6182119442) records the measured alternatives and remaining acceptance work. The live scheduled-capture policy in [ADR 0037](0037-capture-scheduled-backups-live.md) remains unchanged; its former shared-master rationale is historical.
