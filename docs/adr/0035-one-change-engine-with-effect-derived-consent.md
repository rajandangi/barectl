# One change engine with effect-derived consent

Accepted on 2026-10-10 for [#323](https://github.com/rajandangi/barectl/issues/323); not implemented. One engine in the `operations` app owns every change on the target stack: prepare, review, apply natively, verify and reconcile. Each kind of change supplies four parts: an inspection, a pure review, a native body and a verification. A review is stored once, as a typed core plus a versioned document for its kind, and a run keeps a protected reference to the review it applies, instead of each feature keeping its own plan and run model pair.

The review declares the change's effects, and the engine derives its consent level from them: Read, Site, Shared or Destructive. A kind never chooses its own level. A Shared change lists every affected site, read from current evidence, and that list is rechecked under the shared lock; if it changed, the run is refused and needs a new review.

The released features each kept separate plan and run models and their own permission names, about twenty pairs of each. Three Phase A change kinds (host foundation, add runtime, create site) already share the same sequence, and shared PHP-FPM masters make the blast radius of a change, not its feature, the thing an operator must consent to. Reopening the per-feature model is justified because the target stack replaces every feature that used it. The cost is that kind-specific details are no longer queryable columns; reviews are read whole by their own page, and [ADR 0003](0003-store-discovery-snapshots-in-typed-columns.md) still governs discovery snapshots, which are queried.

This reopens the per-feature immutable plan record of [ADR 0005](0005-review-exact-bootstrap-transitions.md): a review stays immutable and bound to fresh evidence, but it is stored once in the engine's record instead of in a model per feature, because twenty near-identical pairs made each new change kind costly and let permissions drift. [ADR 0004](0004-serialize-remote-operations-in-one-table.md)'s single operation table is kept.
