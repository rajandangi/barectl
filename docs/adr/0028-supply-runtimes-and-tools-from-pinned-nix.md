# Supply runtimes and tools from one pinned multi-user Nix

Accepted on 2026-10-10 for [#323](https://github.com/rajandangi/barectl/issues/323), subject to Phase A qualification; not implemented. Supersedes [ADR 0016](0016-limit-third-party-php-supply.md) and the PHP supply and single-default-version rules of [ADR 0008](0008-review-each-ubuntu-release-by-its-own-policy.md) for new servers.

Each server has one multi-user Nix installation, installed by the official installer for an exact release and verified before use, with one pinned nixpkgs commit. Nix supplies PHP CLI and FPM with extensions, Composer, WP-CLI, Node.js, Python, uv and restic. Each runtime is a Nix profile under `/nix/var/nix/profiles/barectl/`, so generations are the rollback candidates and garbage-collection roots, and discovery reads them with ordinary tools. Sites select a runtime; identical builds are shared, never copied per site.

Ubuntu's archive gives one PHP per release, and per-site versions needed a third-party APT source with its own trust, freshness and admission machinery (ADR 0016) that only covered PHP. Nix gives every supported version on both architectures from one reviewed supply, for every language. Ubuntu's `nix-bin` was rejected: it is in universe without updates, and pinning the Nix release keeps it independent of the Ubuntu release. Flakes were rejected while they remain experimental.

The daemon admits only root and an operator group; no one is a trusted user. Site users run store binaries without daemon access. The store is world-readable, so no configuration, credential or user data enters it. The pin moves about every six months, when a nixpkgs stable branch ends, as a reviewed change. Phase A must qualify cold install cost, store size, binary-cache hits for the chosen extension sets, the build sandbox under Ubuntu's AppArmor, atomic profile switches and recovery from a failed switch, before legacy APT-PHP code is removed. Details are in the [target architecture](../target-architecture.md#nix).
