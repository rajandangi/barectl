# Use native bootstrap execution and exclusion

Apply runs submit one finite payload to a uniquely named transient systemd system service, which owns execution after the controller disconnects. Every payload acquires the same nonblocking native flock before validating its boot identity, admission deadline, and reviewed evidence. Pyinfra's shell interface, through the connection `discovery/ssh.py` opens, carries submission and inspection; neither a controller worker nor a local database lock owns remote execution or cross-device exclusion.

This is implemented for reviewed package metadata refresh in `bootstrap/native.py`, the one adapter apply services use, and qualified against the disposable Ubuntu 24.04 server (`bootstrap/test_apply_remote.py`). The control stays unavailable in production (`settings.METADATA_REFRESH_APPLY` is off and not configurable) until cross-controller admission and reconciliation are qualified.

## Submission

`systemd-run --unit=barectl-apply-<32 hex digits>.service --quiet --expand-environment=no --service-type=exec --remain-after-exit -p ExitType=cgroup -p Restart=no -p RuntimeMaxSec=30min -p TimeoutStopSec=60 -p KillMode=control-group -p StandardInput=null -p StandardOutput=journal -p StandardError=journal /usr/bin/sh -c <payload>`, run as root or through `sudo -n` after `sudo -n -l` authorized that exact command line. No `--scope`, `--pty`, `--pipe`, `--wait` or `--collect`; systemd-run returns once the main process was executed, and the SSH connection owns nothing of the unit. The unit name is saved locally when the run is queued. Payloads over 16 KiB are refused, never split. On systemd 255.4 `--expand-environment=no` appears as the `no-env-expand` flag of `ExecStartEx`, and `%` is not expanded in transient command lines.

## Payload

Fixed shell text with validated parameters (unit name, boot ID, deadline in hundredths of a second, SHA-256 digest), each step in the foreground:

1. Create `/run/lock/barectl` with mode 0700 if missing, and refuse unless it is a root-owned directory with mode 0700 (`/run/lock` is world-writable, so another user could have created it). Refuse a symlinked lock file; open `/run/lock/barectl/mutation.lock` for appending, which never truncates or replaces it, and refuse unless it is an empty root-owned regular file with one link. It holds no data.
2. `flock -n` on descriptor 9, which children inherit; failure exits 10. There is no waiting or lock stealing.
3. Under the lock: the boot ID must equal the reviewed one (exit 12), `/proc/uptime` must be before the deadline (exit 13), and no other `barectl-apply-*.service` control group may report `populated 1` (exit 14), since a child can close the lock descriptor and outlive its wrapper. Unsafe lock state exits 11.
4. Recompute the APT digest that preparation recorded: `apt-config dump`, SHA-256 of every file under `/etc/apt` except `auth.conf*`, and `apt-get indextargets --no-release-info` sources, each sorted with `LC_ALL=C`. Any changed configuration, hook, source or preference exits 15. The same text gives the same digest unprivileged over SSH and as root in the service on the acceptance server.
5. `apt-get -q --error-on=any update`, with its output captured and at most 16 KiB of it written to the journal. APT's lists-lock contention fails immediately without waiting (exit 16); a nonzero status or any `W:`, `E:` or `Err:` line exits 17; otherwise exit 0.

## Inspection and outcomes

Inspection reads the boot ID, `systemctl show` of `Id`, `LoadState`, `ActiveState`, `SubState`, `Result`, `ExecMainCode`, `ExecMainStatus` and `InvocationID`, and `populated` from the unit's `cgroup.events`, all unprivileged. A unit is terminal only when nothing remains in its control group and it is `active/exited`, `failed` or `inactive`. Native success is `ExecMainCode=1` (exited), status 0, `Result=success` and an empty control group; `Result=success` alone is not enough. Exits 10 to 16 are refusals before any requested change. `Result=timeout` is a timeout, and a killed main process is a termination. Verification is separate: the authenticated noble, noble-updates and noble-security main indexes for the server's architecture must be present, and `/var/lib/dpkg/status` must be unchanged since before submission.

Acknowledgement is not evidence. The worker records the dispatch before sending; a lost answer, lost connection, unreadable evidence, a run still active after four minutes of watching, or a stopped worker leaves the run reconciling, and Check outcome inspects the same unit name with a new connection, requiring the recorded invocation once known. Nothing is ever submitted again. A unit that is missing stays reconciling with the reason; after a boot change its evidence is gone. Successful and failed units are retained until cleared through ordinary administration; Barectl refuses new submissions when 100 bootstrap units are retained.

## Consequences

- Native service state and native journals are the only execution evidence; private plans and audit records stay in the application database. Native journal retention is the operating system's.
- Timeout and wrapper death are qualified on the disposable server: the runtime limit stops the whole control group and releases the lock, and a descriptor-closing child that outlives its killed wrapper keeps the unit running and blocks admission although the lock is free.
- Transient units do not survive a reboot. A real reboot is not exercised in Docker; a plan from another boot is refused under the lock. Outcome-unknown closure, terminal cleanup, coordinated cleanup under the lock, and exclusion between independent controllers remain to be qualified before production use. See [v0.2](../v0.2.md#native-execution-and-coordination).
