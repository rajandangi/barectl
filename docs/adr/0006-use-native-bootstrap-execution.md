# Use native bootstrap execution and exclusion

Planned apply runs submit one finite payload to a uniquely named transient systemd system service, which owns execution after the controller disconnects. Every payload acquires the same nonblocking native flock before validating its boot identity, admission deadline, and reviewed evidence. Pyinfra owns submission and inspection; neither a controller worker nor a local database lock owns remote execution or cross-device exclusion.

The lock is an empty runtime inode in `/run/lock/barectl/mutation.lock`, beneath a root-owned non-symlink directory with mode 0700. It contains no tracking data and is never unlinked or replaced during its boot. Native service state and native journals are permitted execution evidence; private plans and audit records stay in the application database. Use cgroup-based execution lifetime, require an empty execution cgroup for terminal cleanup, and refuse admission while another bootstrap unit retains execution processes even if its wrapper released the lock. Native success requires normal main-process exit with status zero and completed child execution. Timeout, wrapper death, and descriptor-closing children require actual Ubuntu qualification.

Lost acknowledgement moves the local run into reconciliation without replay. A server-monotonic admission deadline and boot check fence delayed submission. Outcome-unknown closure requires native proof that execution cannot still start or continue, together with explicit acknowledgement; absence of a unit alone proves neither. The service is not reboot-resumable, and missing native history remains missing. See [v0.2](../v0.2.md#native-execution-and-coordination) for lifecycle, privilege, retention, and acceptance requirements.
