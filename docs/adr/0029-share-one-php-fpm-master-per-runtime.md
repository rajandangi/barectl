# Share one PHP-FPM master per runtime, with protected OPcache

Accepted on 2026-10-10 for [#323](https://github.com/rajandangi/barectl/issues/323). The Phase A runtime slice implements profiles, masters and live protection reconstruction; site pools and cross-pool isolation qualification follow separately. A runtime is a named PHP branch and extension set, such as `php84`; its exact build changes by profile generation when a catalog update is applied. It runs one FPM master as an instance of a native systemd template unit, with one pool per site under the site's user and a socket keyed by runtime. A master per site would multiply memory and OPcache on small servers; one master for every version is impossible.

Sharing a master shares its OPcache, whose protections are off by default. Every master therefore sets `opcache.validate_permission=1`, `opcache.validate_root=1` and a root-only `opcache.restrict_api`, with no file cache and no preload; without them one site could be served another site's cached scripts, reset every site's cache or list other sites' paths. Pools also share the master's private `/tmp`, so every pool gets its own session, upload and temporary directories, or one site could read another's sessions. A shared master is not qualified until native tests prove these settings block cross-pool reads.

A new build is applied with a restart, not `USR2`, until a native test proves re-execution safe. Adding or removing a pool reloads the whole master, so pool changes take Shared consent and list every site on that runtime, until a native test proves in-flight requests survive the reload. Master-level settings (extensions, OPcache) are always reviewed as affecting all of them. Per-site limits come from pool settings; systemd limits apply to the master. The trust model is one owner or a trusted team, not mutually hostile tenants. Details are in the [target architecture](../target-architecture.md#php-fpm).


The native runtime identity is the profile's exact catalog store path and generation, never its name or CLI version alone. Unknown paths are reported without adoption; a protection fault blocks dependent pool changes. Read-only reconstruction uses the fixed root-controlled diagnostic script through an unprivileged ondemand pool and root-only socket, preserving master settings rather than masking faults with diagnostic pool overrides. The upstream fcgi client is supplied through the same pinned catalog. See [runtime implementation](../runtimes.md) for files and boundaries. Initial diagnostic pools have one child and a ten-second idle timeout; constrained-host evidence is required separately from provisioned values.

Passive diagnostics require evidence of what the master loaded, not only current disk bytes. The fixed reader holds the existing native mutation lock and requires manager-owned initial-start or supported `ExecReload` timestamps, the matching master-authenticated syslog startup sequence, and unchanged guarded file ctime/mtime strictly before that load. It rechecks native identity and load evidence around the request. Missing, ambiguous, stale or bounded-out evidence refuses the request until an ordinary supported reload or restart establishes a fresh boundary. Direct unbound `USR2` cannot supply that boundary. This assumes ordinary trustworthy native clocks and root administration; it is not adversarial historical attestation. PHP request overrides do not preserve the original loaded values and can be superseded by cached ini `PATH` sections, so they cannot establish passive safety. Version-matched sources and the operational recovery path are recorded in [runtime implementation](../runtimes.md).

The manager's current displayed arguments are insufficient after a manager reset. The reader also requires a nonzero native ExecStart PID/start tuple matching MainPID and ExecMain, plus empty environment-file, pass/unset-environment and drop-in sources. A missing tuple requires an ordinary verified restart; FPM reload only renews configuration load timing. Adding another instance leaves an unchanged shared template and manager intact, preserving the first master's execution evidence.
