# Change server access with native confirm-or-revert

Accepted and implemented in Phase E ([#306](https://github.com/rajandangi/barectl/issues/306), [#308](https://github.com/rajandangi/barectl/issues/308)). Firewall and SSH sign-in changes can cut off the connection that would repair them, and Barectl cannot rely on the controller staying connected; both are kinds of the one change engine ([ADR 0035](0035-one-change-engine-with-effect-derived-consent.md)). Each such payload saves a root-only [recovery preimage](../../GLOSSARY.md) of the files it changes, arms a transient systemd timer whose service restores that preimage and reloads the affected service, then applies and validates the change. The window ends only when the controller opens a new verified SSH connection and stops the timer; any failure to do so lets the server revert on its own. This follows the confirm-or-revert pattern of upstream tools such as `netplan try` and `iptables-apply`, with systemd as the only executor, under the shared mutation lock and cgroup exclusion of [ADR 0006](0006-use-native-bootstrap-execution.md).

A provider console, a persistent Barectl watchdog or an unguarded change were rejected: the first is outside Barectl, the second is an agent, and the third can lock the operator out. The revert is the one payload that waits, for a bounded time, for the mutation lock, so a running renewal or backup delays it rather than cancelling it. Confirmation runs under the lock and never removes a preimage a started revert is using. While a revert is armed, running or failed, every other Barectl mutation refuses. A reboot inside the window loses the transient timer and keeps the new persistent configuration; the review says so, and the restart action refuses while a window is open. Implemented behavior is in [security](../security.md#confirm-or-revert); the [native contract](../security-native-design.md#confirm-or-revert-window) owns the fixed window, preimage paths and verification. The Restart server kind refuses while a window is open or a put-back has failed.
