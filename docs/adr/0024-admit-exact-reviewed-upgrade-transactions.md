# Admit exact reviewed upgrade transactions

Accepted for planned v0.9. [ADR 0007](0007-admit-exact-package-transactions-with-an-inline-apt-guard.md) admits only fresh installations and refuses every upgrade, so routine patching has no reviewed path. Install updates extends the same package engine rather than adding a second one: the plan names each selected package at its reviewed candidate version with `--only-upgrade`, new dependencies are installed only when the guard's approved lines contain them, and the guard admits an upgrade line only when its old and new versions, architectures and archive match the review exactly. Removals, downgrades, held packages, pending dpkg states and packages with locally modified configuration files still refuse, because a configuration prompt cannot be answered safely without operator review.

Running `apt-get upgrade` or unattended-upgrades for the operator was rejected: neither binds the installed transaction to what was reviewed. Ubuntu's own unattended-upgrades remains the automatic path and runs outside Barectl's lock; dpkg's locks keep the two apart, and Barectl mutations refuse while its units run. The [native contract](../security-native-design.md) records the upgrade grammar and service-restart disclosure.
