# Serve sites and HTTPS with Caddy from the pinned Nix catalog

Accepted on 2026-10-10 for [#323](https://github.com/rajandangi/barectl/issues/323); not implemented. Supersedes [ADR 0011](0011-use-native-certbot-renewal-under-shared-exclusion.md), [ADR 0013 (Certbot inhibition)](0013-inhibit-certbot-renewal-until-the-guard-is-verified.md) and [ADR 0014](0014-install-site-certificates-with-one-operator-action.md) for new servers, and the Nginx parts of [ADR 0012](0012-publish-site-files-without-replacing-them.md).

Caddy is the only web server. It serves PHP through FastCGI to per-site FPM sockets, proxies later applications, and owns certificate issuance and renewal, which removes Barectl's Certbot setup, renewal guard and activation state machine. Each site is one file under `/etc/caddy/sites/`, changed by validating the whole tree with the candidate, replacing, reloading and verifying that the running configuration equals the files, with the previous file restored if the reload fails. The previous file is kept only in the plan and run, which amends the server-side backups of [ADR 0012](0012-publish-site-files-without-replacing-them.md). Discovery reads site files through `caddy adapt`, so Barectl has no Caddyfile parser. The admin endpoint is a mode 0600 Unix socket in the unit's runtime directory, which site users cannot reach.

Caddy comes from the pinned Nix catalog of [ADR 0028](0028-supply-runtimes-and-tools-from-pinned-nix.md); nixos-26.05 packages 2.11.7, the current upstream release. Ubuntu 26.04's archive has only 2.6.2, without the 2026 security fixes. Upstream's documented APT repository was the first choice, but on 2026-10-10 a real `apt update` on Ubuntu 26.04 received `402 Payment Required` for its index, so it cannot be relied on. Upstream's signed `.deb` files on GitHub would need a Barectl downloader and verifier. With Nix, Caddy's security fixes take the same reviewed in-branch pin update as PHP's. Barectl owns Caddy's systemd unit, modeled on [upstream's unit](https://raw.githubusercontent.com/caddyserver/dist/master/init/caddy.service), and its `caddy` system user.

Barectl still owns what Caddy does not: explicit deny rules for dotfiles, `wp-config.php` and PHP under uploads, certificate status from files, TLS probes and journald, and DNS and issuance failures shown to the operator. Sources are in the [target architecture](../target-architecture.md#caddy).
