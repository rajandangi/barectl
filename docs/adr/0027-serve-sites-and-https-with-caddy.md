# Serve sites and HTTPS with Caddy from its official repository

Accepted on 2026-10-10 for [#323](https://github.com/rajandangi/barectl/issues/323); not implemented. Supersedes [ADR 0011](0011-use-native-certbot-renewal-under-shared-exclusion.md), [ADR 0013 (Certbot inhibition)](0013-inhibit-certbot-renewal-until-the-guard-is-verified.md) and [ADR 0014](0014-install-site-certificates-with-one-operator-action.md) for new servers, and the Nginx parts of [ADR 0012](0012-publish-site-files-without-replacing-them.md).

Caddy is the only web server. It serves PHP through FastCGI to per-site FPM sockets, proxies later applications, and owns certificate issuance and renewal, which removes Barectl's Certbot setup, renewal guard and activation state machine. Each site is one file under `/etc/caddy/sites/`, changed by validate, replace, reload and verify, with the previous file restored if the reload fails. The admin endpoint is a Unix socket in a `caddy`-owned directory that site users cannot reach.

Ubuntu's archive has only Caddy 2.6.2, without 2026 security fixes, so Caddy comes from upstream's official APT repository with its own keyring, the approved key fingerprint recorded at implementation, and the exact-transaction admission of [ADR 0007](0007-admit-exact-package-transactions-with-an-inline-apt-guard.md). Installing from Nix was rejected because security fixes would then wait for a pin move. This adds a trusted third-party publisher that runs package code as root; no other package may come from that source.

This reopens [ADR 0008](0008-review-each-ubuntu-release-by-its-own-policy.md)'s rule that a third-party source refuses any transaction it offers a package to, for the Caddy package only, because the archive's Caddy cannot be kept secure. ADR 0016's trust terms carry over: a dedicated keyring referenced by the source's `Signed-By`, the full approved fingerprint, no global trust, a new reviewed decision for a new primary key, and refusal of any transaction in which the source offers a package other than `caddy`. ADR 0016's seven-day freshness limit does not carry over until the repository's metadata dates are observed.

Barectl still owns what Caddy does not: explicit deny rules for dotfiles, `wp-config.php` and PHP under uploads, certificate status from files, TLS probes and journald, and DNS and issuance failures shown to the operator. Sources and the open availability check are in the [target architecture](../target-architecture.md#caddy).
