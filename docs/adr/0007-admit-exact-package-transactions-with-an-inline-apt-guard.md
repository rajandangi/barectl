# Admit exact package transactions with an inline APT guard

A reviewed package profile is installed by one `apt-get install` inside the apply payload ([ADR 0006](0006-use-native-bootstrap-execution.md)), and dpkg changes nothing unless APT's actual transaction is exactly the reviewed one. APT's simulation, exact root versions and Barectl's own lock are not that proof: the simulation locks nothing, and the state APT resolves from can change until it holds dpkg's frontend lock. Barectl adds one more `DPkg::Pre-Install-Pkgs` command to that single invocation, the guard, which APT runs after resolving and downloading, while holding the frontend lock, and before it runs dpkg. A guard exiting non-zero makes APT stop before dpkg is called. The engine is profile-agnostic (`bootstrap/native.py`: `package_digest`, `guard`, `package_change`); a profile supplies its units, configuration directories, listener port or socket, the directories whose entries it fixes, and its syntax check. The Nginx and PHP 8.3 profiles use it unchanged.

## Revalidation under the mutation lock

A package plan records two digests that the payload recomputes as root after taking the mutation lock and checking the boot and deadline: the APT digest of ADR 0006, and a package digest of dpkg's status file (package states, holds, configuration files), APT's automatic marks, the downloaded Release files and the name, size and modification time of every downloaded index, the profile's units (load, activity, enablement, unit file, drop-ins), every entry and file digest under its configuration directories, the entries directly under the directories whose layout it fixes, ucf's registry where the profile's files are ucf's, and the addresses listening on its port or at its socket. Preparation reads the same shell text unprivileged before and after its other package and service reads and refuses the plan if they differ. Any difference under the lock exits 15 before APT runs. A metadata refresh dispatched after the review also refuses the plan, at the controller and again in the worker.

## Installation

`DEBIAN_FRONTEND=noninteractive apt-get -q -y --no-remove -o APT::Install-Recommends=0 -o APT::Install-Suggests=0 -o APT::Get::Fix-Missing=0 -o DPkg::Pre-Install-Pkgs::=<guard> -o DPkg::Tools::Options::barectl_package_guard()::Version=3 install <root>=<version>`, with standard input from `/dev/null`:

- Only the plan's missing root packages are named, each at its reviewed version, so APT marks only them manual and the dependencies automatic. The reviewed closure goes to the guard, never to APT as roots.
- No `--allow-*` or `--force-*` option and no `Dpkg::Options`. `-y` answers APT's own confirmation only; anything that needs an `--allow` option (held packages, downgrades, removals of essential packages, unauthenticated packages) still fails. A dpkg configuration-file prompt reads end of file and fails; a fresh installation has none, and leftover configuration is refused at review.
- `--no-remove` and `Fix-Missing=0` make any removal or missing archive fail. Package plans refuse sources whose scheme is not `http` or `https`, and the guard admits only archives in `/var/cache/apt/archives`, so removable media and local repositories, which APT reads in place, are refused.
- The distribution's configuration applies unchanged: the existing Pre-Install-Pkgs commands run before the guard, since `-o …::=` appends to the list; recommends stay off exactly as in the preview's simulation; needrestart and the maintainer scripts behave as on any installation.
- APT's default `DPkg::Lock::Timeout` of 0 for `apt-get` makes it fail at once when another process holds `/var/lib/dpkg/lock-frontend`; the payload maps that to exit 16 without waiting.

Before APT runs, the payload records the SHA-256 of `/var/lib/dpkg/status` and passes it to the guard in `BARECTL_DPKG_STATUS`. Afterwards it compares the file again. Unchanged status means dpkg changed nothing: the guard's refusal line exits 21, a lock message 16, APT having nothing to do 15, and any other APT failure 23. Changed status requires APT to have succeeded after exactly one admission line, or exits 20 (dpkg changed packages; the installation may be partial). A service-only plan runs `systemctl enable` and `systemctl start` for its reviewed effects instead (exit 22 on refusal). Every package payload then runs the profile's syntax check as root, `nginx -t -q` for Nginx and `php-fpm8.3 -t` for PHP (exit 24).

## The guard

APT runs each Pre-Install-Pkgs value with `/bin/sh -c` and, in protocol version 3, writes to its standard input `VERSION 3`, the configuration space, a blank line, and one line per dpkg action: package name, old version, old architecture, old Multi-Arch type, direction, new version, new architecture, new Multi-Arch type, and the archive path, `**CONFIGURE**` or `**REMOVE**`. The version for a command is read from `DPkg::Tools::Options::<first word of the command>::Version`; the guard's first word is its function definition, `barectl_package_guard()`. The guard is fixed text with the approved actions embedded as literal sorted lines; nothing is written to the server. It refuses, printing `barectl-guard: refused <reason>`, unless:

- `DPKG_FRONTEND_LOCKED=true` (APT holds the frontend lock) and `APT_HOOK_INFO_FD=0`;
- dpkg's status still has the digest the payload recorded, so neither another process nor an earlier Pre-Install-Pkgs command changed it after revalidation;
- the input starts with `VERSION 3`, the configuration section ends with a blank line, and the input ends with a complete line;
- every action line has exactly nine single-space-separated fields, no old version (`- - none`, or `- - no`), direction `<`, a documented Multi-Arch type, and either `**CONFIGURE**` or an archive directly under `/var/cache/apt/archives/`;
- the actions, normalized to `U <package> <version> <architecture> <archive file>` and `C <package> <version> <architecture>` and sorted, equal the approved lines exactly. The archive file name is the one APT gives downloaded archives, with `:` in the version encoded as `%3a`.

Upgrades, downgrades, reinstalls, removals, configure-only actions for pending packages, changed versions or architectures, extra, missing or repeated actions, and a partial round of a split installation therefore all refuse, and a second invocation can only be admitted with the complete transaction again, which the payload's one-admission rule rejects. On success it prints `barectl-guard: admitted`.

## Evidence

Qualified on the disposable Ubuntu 24.04.5 arm64 server with apt 2.8.3, dpkg 1.22.6ubuntu6.6, debconf 1.5.86ubuntu1, apt-utils 2.8.3, needrestart 3.6-7ubuntu4.5 and systemd 255.4-1ubuntu8.17 (`bootstrap/test_package_remote.py`): the unit's journal shows debconf's `Preconfiguring packages`, then the admission, then dpkg's first unpack; a non-zero guard leaves dpkg's status, dpkg's log and the automatic marks unchanged for a missing dependency, an extra package, another version, another architecture, unpacks without configuration and configuration without unpacks; changes between review and the lock refuse as drift before APT runs; a dependency installed after revalidation is refused by the guard, a hold placed after revalidation by APT itself, and a dpkg selection changed by an earlier Pre-Install-Pkgs command by the guard's status check, before dpkg unpacks anything (recorded as exit 20, since dpkg's status did change); a held frontend lock refuses at once; the guard's parser refuses malformed, truncated and unknown input under dash. Successful runs keep every earlier package's automatic mark, mark the root manual and the new dependencies automatic. The PHP 8.3 profile passed the same engine unchanged on that server (`bootstrap/test_php_remote.py`, php8.3 8.3.6-0ubuntu0.24.04.11): the guard admitted `php-common` 2:93ubuntu2 from `php-common_2%3a93ubuntu2_all.deb`, the package digest read unprivileged at review, including `/var/lib/ucf/hashfile`, equalled the one root recomputed under the lock, and with `php8.3-cli` already installed and automatic only `php8.3-fpm` was named and `php8.3-cli` stayed automatic. Locally only arm64 is exercised; CI's disposable-server job runs the same suite on amd64.

## Consequences

- debconf's hook runs before the guard on every installation: it extracts the downloaded packages' templates and runs their configuration scripts with the noninteractive frontend, which records default answers in debconf's database. It does not call dpkg to change packages, and the guard's status check proves dpkg's state was not changed before it. The guard cannot undo what debconf recorded; the review says so. Any other Pre-Install-Pkgs command is an unknown hook and refuses the plan.
- APT downloads and keeps the archives before the guard runs, so a refusal can leave them in `/var/cache/apt/archives`.
- The package's maintainer scripts enable and start the service, and needrestart may restart services, before Barectl validates anything. Validation after the changes (syntax check, package versions and health, marks, unit, listeners) never rolls back; a failure is recorded with the known execution outcome and recovery through ordinary administration.
- A root process that ignores dpkg's frontend lock can still change the server between the guard and dpkg; that is outside the coordination contract.
- Sources: Noble [apt-get(8)](https://manpages.ubuntu.com/manpages/noble/man8/apt-get.8.html) and [apt.conf(5)](https://manpages.ubuntu.com/manpages/noble/man5/apt.conf.5.html) (`DPkg::Pre-Install-Pkgs`, protocol versions, `DPkg::Tools::Options::cmd::Version`); APT 2.8.3 [dpkgpm.cc](https://salsa.debian.org/apt-team/apt/-/blob/2.8.3/apt-pkg/deb/dpkgpm.cc) (`SendPkgsInfo`, `RunScriptsWithPkgs`, `ExpandPendingCalls`, and `Go`, which returns before writing automatic marks or calling dpkg when a pre-install command fails), [private-install.cc](https://salsa.debian.org/apt-team/apt/-/blob/2.8.3/apt-private/private-install.cc) (`Fix-Missing`, media-swapping rounds) and [debsystem.cc](https://salsa.debian.org/apt-team/apt/-/blob/2.8.3/apt-pkg/deb/debsystem.cc) (`DPkg::Lock::Timeout` default 0, `DPKG_FRONTEND_LOCKED`); [Ubuntu's Nginx installation guide](https://ubuntu.com/server/docs/how-to/web-services/install-nginx/) and [Noble needrestart changes](https://discourse.ubuntu.com/t/needrestart-changes-in-ubuntu-24-04-service-restarts/44671). That a failing guard leaves dpkg's status and log untouched, that `apt-get` fails at once on a held frontend lock, and the order of debconf's hook, the guard and dpkg are Barectl's observations of apt 2.8.3, not upstream guarantees.
