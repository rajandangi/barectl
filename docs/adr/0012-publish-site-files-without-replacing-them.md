# Publish site files without replacing them, and report each boundary

> The Nginx publication, from [Publication](#publication) on, was deleted at the Phase A exit ([#341](https://github.com/rajandangi/barectl/issues/341)); [ADR 0027](0027-serve-sites-and-https-with-caddy.md) supersedes it. [Target-stack HTTP publication](#target-stack-http-publication) is current, with the serving of [ADR 0038](0038-drain-site-php-through-private-haproxy.md): a new site starts its own PHP-FPM master and joins no shared master.

A site run creates an account, directories, files and a link, and reloads two services. These cannot form one transaction, so the payload publishes each file in a way that can fail but never replaces anything, reports how far it got by its exit status, and compensates only the two steps whose after-state it can prove it made. Implemented in `sites/native.py` (the payload) and `sites/apply.py` (outcomes and verification); qualified on the disposable Ubuntu 24.04 and 26.04 servers ([qualification](https://github.com/rajandangi/barectl/blob/60a00b8f4eb11eeccf6797f0053a4dfe7b081942/docs/v0.3-qualification.md#site-creation)).

## Target-stack HTTP publication

The revision-5 implementation uses the existing operations engine's four operational members and sole SSH adapter. Its native body holds the shared mutation lock, rechecks the reviewed native files and loaded PHP state, and holds the stable site deployment lock while creating the release layout, pool and Caddy route. Current affected membership is bound separately to the selected PHP master, including an explicitly empty set; creating the new site does not treat that new identifier as an already affected worker.

Review and apply validate the actual complete candidate Caddy tree as the caddy identity. Caddy validation provisions log writers, whose future absolute site path may not yet exist. A bounded root-owned temporary tree under `/run` contains copied Caddy configuration and scoped directory metadata. A child util-linux mount namespace, with private propagation, binds its scratch `/var` and invokes the pinned native validator through `runuser`. Candidate bytes and absolute paths are unchanged. The live `/var` and parent mount namespace remain untouched; unavailable namespace privileges mean unavailable validation, never cached approval. Temporary files are removed on success and refusal.

Publication rechecks the live preimage, stages on the destination filesystem, syncs and atomically replaces the site file. After native reload, loaded JSON must equal disk adaptation. A rejected load restores the previous bytes and proves both old adaptation and old serving state before reporting unchanged. If a candidate might have served, restoration cannot establish an unchanged outcome. Creation already performed before a failed Caddy load remains partial; account, layout and pool creation are not one transaction.

Application content is outside passive drift hashing. Source and public-asset permissions, root-owned wrappers, release links and deployment lock are defined by the [site convention](../site-conventions.md). Qualification remains tied to the exact tested revision; this implementation does not qualify the whole Phase A stack.

## Publication

The payload runs under the mutation lock of [ADR 0006](0006-use-native-bootstrap-execution.md) with `umask 077` and `set -C`. Every interpolated file path, owner, group, mode and template must match the convention or nothing is submitted. Configuration files are staged beside their destinations as `.<name>.<32 hex digits of the unit>`, outside Nginx's and PHP-FPM's include patterns. Before staging and publishing, the destination directory and every ancestor must remain root-owned, not symbolic links, and writable by nobody else. The stage gets its reviewed owner and mode, is synced, and its SHA-256 must match the review. `ln -T` then publishes only at an absent destination: `link(2)` refuses replacement and `-T` prevents following a destination directory. The stage is removed and its directory synced. The enablement link uses `ln -sT`. A stage whose publication failed stays for inspection.

A creation or finish plan replaces nothing. Its review requires each proposed destination to be absent and every retained resource to match exactly, so no preimage backup is made. [ADR 0015](0015-recognize-only-the-convention.md) supersedes the original no-finish rule. A retained account keeps its reviewed attributes and exact UID and GID.

Content published into the site-owned document root is staged in the root-owned site boundary. Its stage stays root-owned with mode 0600 through the digest check and `ln -T` publication, so the site user cannot change the checked bytes. Final ownership and mode are applied through that trusted stage path before it is removed, rather than through a destination the site user can rename. The boundary and ancestors remain root-controlled, and the document root must retain its reviewed identity and permissions. A placeholder is published only when this run creates the public directory. An existing public directory's application content is neither interpreted nor changed.

The account is created with the reviewed `useradd` command and its explicit flags, one definition for the review and the payload, under useradd's own lock; its actual IDs are read back and must match the review before any ownership uses them.

## Replacement

A challenge route replaces the site file in place ([TLS](https://github.com/rajandangi/barectl/blob/60a00b8f4eb11eeccf6797f0053a4dfe7b081942/docs/tls.md#applying)), the first action that does. The reviewed preimage's SHA-256 is rechecked under the lock with the file's type, owner, mode and single link; the file is then copied to a root-only backup named after the run's unit, whose bytes must equal the preimage's. The candidate is staged beside the file as `.<name>.<unit>`, checked against its reviewed digest, and renamed over the file with `mv -T` only while the file still has the preimage's bytes and every directory above it is root's; otherwise the stage is removed and the file kept. If `nginx -t` refuses the candidate, a staged copy of the backup is renamed back while the file still has the candidate's bytes, `nginx -t` runs again, and nothing is reloaded. The backup is kept after success and failure; it is recovery material an administrator uses, never evidence Barectl reads as current state.

## Order

The pool is published, checked with `php-fpm -t` and loaded first, and its socket must exist, owned by `www-data` with mode 0600 and listening, before the Nginx site file and link are published. The PHP runtime identity is proven afterwards, through the enabled site, by the temporary probe, whose answer must be the site user's IDs before the run can succeed. This is how the specification's "verify the pool, socket and identity before the site entry" is met: the socket before the entry, the identity before success.

## Boundaries

After the admission exits of ADR 0006, exit 15 means nothing was changed because the reviewed site digest differs, a destination exists, a parent directory is unsafe, or `useradd`, `nginx`, `php-fpm` or the PHP CLI is missing. Each later exit status names the boundary the run reached. 31 means useradd failed and the account databases are unchanged; it is a refusal before changes. 40 to 55 are partial completion: 40 useradd failed after the databases changed, 41 the account differs from the review, 42 directories, 43 content, 44 the pool file, 45 the pool withdrawn with a valid configuration, 46 an invalid configuration, 47 the PHP-FPM reload, 48 the socket, 49 the site file, 50 the link, 51 the link withdrawn with a valid configuration, 52 an invalid configuration, 53 the Nginx reload, 54 not serving as reviewed, 55 the probe left. The run keeps the raw exit status; the pages turn it into what exists and the ordinary administration that completes or removes it ([recovering a partial site](https://github.com/rajandangi/barectl/blob/60a00b8f4eb11eeccf6797f0053a4dfe7b081942/docs/sites.md#recovering-a-partial-site)). A killed wrapper, a timeout or a reboot leaves the boundary unknown; a new review shows the current state.

## Compensation

Only two changes are undone, both under the lock and only while their after-state is still the run's own: a pool file created by this run that `php-fpm -t` rejects is removed if it still has the reviewed bytes, owner and mode, before any reload; a link created by this run that `nginx -t` rejects is removed if it is still root's and points to the reviewed file. Either is followed by the same syntax check. Nothing is undone after a reload. Accounts, directories, content and anything an operator or application wrote are never removed, and an interrupted unit is never replayed. A new reviewed Finish plan may create only missing resources while every existing resource remains exact, as [ADR 0015](0015-recognize-only-the-convention.md) requires. The temporary probe retains a hard link at `/var/www/<id>/.probe-<token>.php.<unit>.anchor` in the root-owned boundary. Cleanup atomically moves its public pathname to `.probe-<token>.php.<unit>.quarantine` there using `mv --no-copy --no-clobber -T`, then checks that the captured entry is the anchor's exact inode, with the reviewed metadata and bytes. Only that proven probe and its anchor are removed. A replacement application entry is restored without overwriting anything; if restoration is blocked, it remains in quarantine. A newly occupied public pathname is kept. Any changed, missing or unremovable probe reports exit 55, incomplete verification, whatever boundary it reached. Recovery material is never used as discovery authority.

The [GNU mv documentation](https://www.gnu.org/software/coreutils/manual/html_node/mv-invocation.html) and the installed release's [Resolute](https://manpages.ubuntu.com/manpages/resolute/man1/mv.1.html) manual document `--no-copy`: cleanup must refuse a cross-filesystem rename rather than copy and delete an entry. Barectl checks the captured entry after the move because no-clobber can skip an occupied destination. This is a Barectl preservation requirement implemented with the existing native file publication tools.

## Later actions

Later actions publish their own files the same way, and only into directories root owns. A database binding's temporary probe is staged and published in the root-owned `/var/www/<id>`, never in the document root, which the site user owns: a stage in a directory another user can write could be replaced or linked by that user between the root chown and the link ([ADR 0013](0013-create-a-database-binding-statement-by-statement.md#proof-through-the-pool)).

## Limit

The lock is cooperative. It excludes Barectl runs from every controller and alias of a server, and the payload rechecks every destination and its directory immediately before publishing, but a root administrator writing outside the lock between that check and the publication is not serialized.
