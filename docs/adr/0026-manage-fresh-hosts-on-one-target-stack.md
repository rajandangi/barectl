# Manage fresh hosts on one target stack

Accepted on 2026-10-10 for [#323](https://github.com/rajandangi/barectl/issues/323); not implemented. New servers get one stack: Ubuntu 26.04 LTS with Caddy, Nix-supplied runtimes, shared PHP-FPM masters, per-site Valkey, native databases, systemd automation and restic ([target architecture](../target-architecture.md)). V1 provisions only fresh, qualified Ubuntu 26.04 hosts. Ubuntu 24.04 is not supported on the target stack: a second release doubles every native test and qualification for no current need. A later LTS is added by its own reviewed release policy.

Every discovery and review judges a server's standing from native evidence, with no marker file: Fresh host, Incomplete foundation, Target stack or Not manageable ([host standing](../target-architecture.md#host-standing)). A host with another web stack, PHP, panel or foreign Nix, and any server set up by earlier Barectl builds or other panels, is Not manageable: Barectl shows why and never rewrites it.

Supporting the released Nginx, Certbot and APT-PHP layout alongside the new one would double every convention, discovery rule and native test. Barectl is in early development with no installations to migrate, so breaking changes are cheaper than a dual stack. The old-stack code and its native tests are deleted when Phase A ships, before the Phase B replacements for HTTPS, WordPress and databases exist; until then the main branch has none of those workflows. This replaces the earlier rule that legacy code stays until its replacement passes: keeping it meant maintaining and testing two stacks through Phase B, inside the build budget of [ADR 0033](0033-prove-real-behavior-in-two-test-layers.md), for software nobody runs.

For the new stack, discovery adopts administrator changes that stay within the supported settings, such as an added Caddy directive the parser understands, instead of requiring byte-exact files. A resource with a setting Barectl does not interpret is Outside supported settings: reported once, blocking only the changes that depend on it. This reverses the byte-exact rule of [ADR 0015](0015-recognize-only-the-convention.md) for new-stack resources, because exact bytes made ordinary administration look foreign. ADR 0015's other rules still hold: no server-side manifest, judgment by native evidence whoever made it, one report per unsupported item, and only dependent mutations blocked.
