# Keep secrets in private native files, delivered over SSH standard input

Accepted on 2026-10-10 for [#323](https://github.com/rajandangi/barectl/issues/323); implemented for site secrets in [#374](https://github.com/rajandangi/barectl/issues/374). Operators add, replace, rotate and remove application settings and secrets in the dashboard. The authoritative copy is on the server in private site-owned files: Laravel's `.env`, and for WordPress a private file outside the web root loaded by `wp-config.php`. The controller database never holds a secret value readable at rest, and the Nix store never holds one at all.

A value typed in an authenticated, CSRF-protected request must reach the worker, which owns SSH. The worker mints a random sealing key when it starts and holds it in memory; the controller account's private key file (`BARECTL_CONFIDENTIAL_KEY`, mode 0600) carries that key between the request handler and the worker. The request seals the value with it and stores only the ciphertext in the run's row. After a worker restart the key is replaced, so the value can no longer be read and the run fails as expired; a value not sent within 10 minutes fails the same way, and once sent the stored value is cleared. A synchronous SSH call from the web request, a new local socket to the worker, and a static key derived from settings were rejected: the first breaks the rule that only the worker connects, the second adds a mechanism with its own failures, and the third leaves the secret readable at rest for as long as the settings live. The key file is controller-private state like the SSH keys, not an application database record, and it is replaced on every worker start.

The worker passes the value as standard input to `RemoteShell.run`, which hands it to pyinfra and never logs it. Two commands run on the same connection. The first is a fixed root command that writes standard input into a root-only directory on tmpfs. The second submits the ordinary transient unit of [ADR 0006](0006-use-native-bootstrap-execution.md), whose payload checks, consumes and removes the staged file on every exit path: the payload's own trap covers a refusal before the kind's body runs, and the body traps `EXIT INT TERM` to cover failure and timeout. A secret therefore never rides in unit properties, which are readable and journaled, and never appears in argv, the journal, operation records, events or responses; a canary test in the fast layer checks each of these. This amends ADR 0006 with the staging command only: the transient unit, shared lock, finite execution and no-replay rules stay as they are, and no second connection or execution service is added.

systemd credentials were considered for everything, but FPM pools cannot read them: the credentials directory belongs to the unit's user, which is root for the master, and `env[]` exposes values the way `Environment=` does. Worker and timer units running as the site user may use `LoadCredential=`. Secrets are write-only in the interface; any future reveal is a separate audited permission. Details are in the [target architecture](../target-architecture.md#settings-and-secrets).
