# v0.3 implementation tickets

All implementation tickets below are merged and closed. Parent specification [#144](https://github.com/rajandangi/barectl/issues/144) remains open until final qualification and release. The public Let's Encrypt staging gate passed, as recorded in the qualification record. The [qualification record](v0.3-qualification.md) identifies the tested revisions, environments and remaining limits. The table preserves the delivery dependencies used during implementation.

PostgreSQL bootstrap depends on MariaDB bootstrap only for the minimal shared profile/postcondition extension it introduces; the server does not need MariaDB installed to use PostgreSQL. The implementation must keep both profiles independently usable.

Each mutating ticket includes its own real serving/access, authorization, drift, fault, reconciliation and reconstruction gates. The final qualification ticket integrates evidence and operator instructions; it cannot excuse a missing safety gate in an earlier slice. Keep the parent and child issues open until their stated work and literal gates are complete.

The [specification](v0.3.md), [native convention](site-conventions.md), [decision/source record](v0.3-decisions.md), and ADRs 0009 through 0011 are the design handoff. No production server mutation or v0.3 implementation was needed to prepare these tickets.
