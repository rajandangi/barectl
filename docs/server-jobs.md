# Server Jobs

Server Jobs is specified by [#284](https://github.com/rajandangi/barectl/issues/284), which is the single source of truth. Where this page or the old v0.7 text differed, the issue wins.

Implemented today ([#285](https://github.com/rajandangi/barectl/issues/285)): a server **Jobs** section after Activity with Last checked, Needs attention, Running, Automatic work and Recent results; an explicit **Check now** that queues ordinary discovery; and the **Barectl changes** provider. Running work comes from the retained `barectl-apply-*` unit state. Finished work comes from one bounded `journalctl` read of the engine's stage and result lines, parsed by the change engine's one result-line parser, so a finished run is named by its kind and sites even when another controller started it. Rows this installation recorded link to their run; others say they started on another computer. Per-provider coverage records no evidence, denied access, unreadable lines, a failed read, truncation and the oldest journal time the server still holds.

Automatic work is empty until [#289](https://github.com/rajandangi/barectl/issues/289) lands. Backup runs and schedules are [#286](https://github.com/rajandangi/barectl/issues/286). Ranges, filters and viewer time zones are [#291](https://github.com/rajandangi/barectl/issues/291). Qualification is [#413](https://github.com/rajandangi/barectl/issues/413).
