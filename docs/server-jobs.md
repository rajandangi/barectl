# Server Jobs

Server Jobs is specified by [#284](https://github.com/rajandangi/barectl/issues/284), which is the single source of truth. Where this page or the old v0.7 text differed, the issue wins.

Implemented today ([#285](https://github.com/rajandangi/barectl/issues/285), [#289](https://github.com/rajandangi/barectl/issues/289)): a server **Jobs** section after Activity with Last checked, Needs attention, Running, Automatic work and Recent results; an explicit **Check now** that queues ordinary discovery; the **Barectl changes** provider; and the **Automatic work** provider. Running work comes from the retained `barectl-apply-*` unit state. Finished work comes from one bounded `journalctl` read of the engine's stage and result lines, parsed by the change engine's one result-line parser, so a finished run is named by its kind and sites even when another controller started it. Rows this installation recorded link to their run; others say they started on another computer. Per-provider coverage records no evidence, denied access, unreadable lines, a failed read, truncation and the oldest journal time the server still holds. Automatic work lists each site's scheduled tasks, queue workers and object cache from Phase C's stored projection, marks its attention states in Needs attention, takes the next run from systemd's next elapse only, and links each row to the site's Settings entry without adding a control.

The **Backups** provider ([#286](https://github.com/rajandangi/barectl/issues/286)) lists each site's recent capture, offsite copy, integrity check and cleanup runs from Phase D's safe result lines, and its backup, check and cleanup timers from systemd. Each run keeps onsite and offsite findings apart, so an offsite failure never hides a usable onsite point; a lock skip is Skipped, never a backup; a missing result line is Could not confirm. Rows link to the site's Backups section and add no backup, restore, keep or retry control. Jobs still runs no restic command, lists no snapshot and contacts no storage; it reads the one bounded passive observation. Failed, partial and skipped runs appear in Needs attention with the same Phase D sentence the site's Backups section uses. Backup rows expose their site and Type of work to the same filters, and remain visible without the change-history permission.

Ranges, filters and viewer time zones are [#291](https://github.com/rajandangi/barectl/issues/291): Recent results offers Today, Past 7 days (default) and Past 30 days plus optional Site, Type of work and Result filters, evaluated in the viewer's named IANA zone and reading saved rows only. Without a valid zone the page shows labelled UTC. Qualification is [#413](https://github.com/rajandangi/barectl/issues/413).
