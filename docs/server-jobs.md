# Server Jobs

Server Jobs is specified by [#284](https://github.com/rajandangi/barectl/issues/284), which is the single source of truth. Where this page or the old v0.7 text differed, the issue wins.

Implemented today ([#285](https://github.com/rajandangi/barectl/issues/285), [#289](https://github.com/rajandangi/barectl/issues/289)): a server **Jobs** section after Activity with Last checked, Needs attention, Running, Automatic work and Recent results; an explicit **Check now** that queues ordinary discovery; the **Barectl changes** provider; and the **Automatic work** provider. Running work comes from the retained `barectl-apply-*` unit state. Finished work comes from one bounded `journalctl` read of the engine's stage and result lines, parsed by the change engine's one result-line parser, so a finished run is named by its kind and sites even when another controller started it. A run written before the result line carried the kind and sites, or a line without them, stays **A Barectl change** with no site. Rows this installation recorded link to their run; others say they started on another computer. Per-provider coverage records no evidence, denied access, unreadable lines, a failed read, truncation and the oldest journal time the server still holds. When that oldest time falls after the start of the chosen range, the page says where the server's retained history starts; an empty list says **No available** results and never that nothing ran. The read asks for one line beyond its 90-line cap, so a full answer and a capped one are told apart; Barectl keeps only the unit, invocation, server times and parsed outcome, never the journal message text. While a check is queued or running, and after it fails, the previous results stay with their own Last checked time and a freshness notice. Automatic work lists each site's scheduled tasks, queue workers and object cache from Phase C's stored projection, marks its attention states in Needs attention, takes the next run from systemd's next elapse only, and links each row to the site's Settings entry without adding a control.

The **Backups** provider ([#286](https://github.com/rajandangi/barectl/issues/286)) lists each site's recent capture, offsite copy, integrity check and cleanup runs from Phase D's safe result lines, and its backup, check and cleanup timers from systemd. Each run keeps onsite and offsite findings apart, so an offsite failure never hides a usable onsite point; a lock skip is Skipped, never a backup; a missing result line is Could not confirm. Rows link to the site's Backups section and add no backup, restore, keep or retry control. Jobs still runs no restic command, lists no snapshot and contacts no storage; it reads the one bounded passive observation. Failed, partial and skipped runs appear in Needs attention with the same Phase D sentence the site's Backups section uses. Backup rows expose their site and Type of work to the same filters, and remain visible without the change-history permission.

Ranges, filters and viewer time zones are [#291](https://github.com/rajandangi/barectl/issues/291): Recent results offers Today, Past 7 days (default) and Past 30 days plus optional Site, Type of work and Result filters, evaluated in the viewer's named IANA zone and reading saved rows only. A range selects the evidence the server still keeps; it never promises how long the server retains it. Without a valid zone the page shows labelled UTC.

Opening Jobs, changing a filter and opening a row read the saved snapshot and open no SSH connection; **Check now** is the only action and it queues the ordinary discovery worker. The page, Automatic work and Backups need `view_server`; change rows, their details, counts and filter options also need `view_changes`, and **Check now** needs the existing discovery-request authority and CSRF. A non-root SSH user reads only what it may read: without the engine's exact `sudo -n` authorization the Barectl changes provider reports access denied and nothing escalates. Servers that are not on the target stack show one sentence instead of rows. Certificates are not a Jobs provider: Caddy renews inside `caddy.service`, and the site's HTTPS section owns certificate state. Qualification is [#413](https://github.com/rajandangi/barectl/issues/413).
