## Upgrade and compatibility

Native contract version **2** remains in force. A 1.0.1 controller reads a result written
by a 1.1.0 or 1.2.0 controller as **Outside supported settings** and refuses changes.
Upgrade every controller before applying changes from either newer version.

A 1.2.0 controller also refuses changes when fresh discovery reads any retained explicit
contract-1 result, including mixed contract-1/contract-2 history. There is no in-app
result-line migration or override. Pre-field contract-0 evidence and no-result histories
remain recognized. The bounded recent-history read gives no promised end date for a
refusal. Do not delete or rewrite audit history to bypass it. See
[native contracts](contracts.md#retained-result-lines) and the
[upgrade guide](upgrade.md#mixed-controller-versions).

Upgrading from 1.1.0 adds no controller database migration. The existing 0.4.x and
1.0.x migrations still apply on those paths. The controller migration boundary stays
at 0.4.0; a 0.3.x or older database needs a new installation. Installing this release
does not apply server settings or runtime catalog updates. Use the stop, backup,
install, upgrade and verification procedure in the [upgrade guide](upgrade.md).

## Limits carried forward

The [1.0 qualification](v1.0-qualification.md#not-qualified),
[1.1.0 qualification](v1.1.0-qualification.md#limits-carried-forward) and
[recovery guarantees](recovery-guarantees.md) retain their limits. Container results
do not add real-provider small-host or reboot coverage. The pinned cloud-image VM
download correction does not qualify a new provider or hosting configuration. Private
management-host deployment and an optional shared database remain unqualified; the
default controller uses its local SQLite database. Journal retention still does not
guarantee a specific history or immediate free disk space.
