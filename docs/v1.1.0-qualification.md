# v1.1.0 release qualification

Release date: 2026-11-15. The annotated `v1.1.0` tag identifies the final release
commit. Publication requires the Checks and Native workflows, including all five
required checks, to pass on that exact commit. The release notes link those runs.

## Scope and revisions

This release includes the application through
`8da27771e0335d3d3234f8deece28190d0f57e73`, plus release metadata and documentation
corrections. The release preparation changes no application behavior, dependencies,
native commands, native bodies or transcript pins.

## Upgrade and compatibility

Native contract version **2** adds journal retention without changing version-1 native
shapes. Every 1.1.0 change writes contract 2, which an older 1.0.1 controller reports
as Outside supported settings. Upgrade every controller before applying any 1.1.0
change. See [native contracts](contracts.md) and
[mixed controller versions](upgrade.md#mixed-controller-versions).

Controller database migration is separate from native admission. Version 1.1.0 refuses
every change if fresh discovery reads any retained explicit contract-1 result, even in
a mixed contract-1/contract-2 history. It offers no result-line migration or override.
Pre-field contract-0 evidence and no-result histories remain recognized. The bounded
recent-history read does not establish an exact blocking duration, and audit history
must not be deleted or rewritten to bypass this limit.

Compared with v1.0.1, the controller adds
`discovery.0022_discoverysnapshot_journal_retention_disk_cap_and_more`. Compared with
v1.0.0, it also includes `operations.0008_check_progress`. Use the documented
`barectl_upgrade` procedure with a database and `.env` backup; installing the controller
does not apply server settings or runtime catalog updates.

The controller database migration boundary remains v0.4.x and later. v0.3.x and earlier
require a new controller database and do not become upgradeable in this release.

## Limits carried forward

The [1.0 qualification](v1.0-qualification.md#not-qualified) and
[recovery guarantees](recovery-guarantees.md) retain their explicit limits. Real-provider
small-host and reboot coverage is not added by container results. Hosting the controller
on a private management host and optional shared-database support are not newly qualified;
the supported default remains the local controller and SQLite database.

Setting journal retention does not guarantee a particular history remains available or
free disk space immediately. Journald owns rotation and vacuuming. Barectl changes and
verifies the documented policy; it does not delete logs or invoke a vacuum command.
