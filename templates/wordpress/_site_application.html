This is passive evidence from the last connection check, read from native files and fixed database queries. Barectl did not run WordPress, WP-CLI or any plugin to collect it, and file presence alone is never proof of an installation. Evidence Barectl cannot read is shown as unread, never as absent. An explicit WordPress inspection that runs application code is a separate operation with its own authorization.

The application's state is independent of the site's infrastructure: changed WordPress content never makes the site's Nginx, PHP-FPM, account or certificate resources look changed.
