This is an explicit operation, not passive evidence. The WordPress application card above is read from native files and fixed database queries and runs no application code. An inspection runs WP-CLI against the installed application as the site user, which can execute WordPress core, must-use plugins and drop-ins; its review names exactly what runs. It needs its own permission. Barectl changes nothing on the server, though WordPress may write its own transients and caches to its database when it loads.

Inspect WordPress
Use it to see what is installed: whether WP-CLI finds the installation, the core release, and the plugins, must-use plugins, drop-ins and themes with their status and version.
Verify core checksums
Use it to find core files that differ from the official release. It reports a match, a mismatch or that the checksums were unavailable, which is neither a pass nor a mismatch.
Verify repository plugin checksums
Use it for plugins installed from WordPress.org. Private or custom packages and plugins without a published catalog are unavailable, never trusted and never reported corrupt.

Preparing a review reads the server and changes nothing. Applying the review is a separate action on its plan page and runs one native unit that outlives this page. A repair, an update, a cache or rewrite flush or any other change is not part of an inspection.
