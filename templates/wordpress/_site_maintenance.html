Maintain WordPress

{% include "servers/_snapshot_notice.html" with notice=site_page.stale %}

Maintenance runs WordPress and changes application state. It runs WP-CLI against the installed application as the site user, which executes WordPress core, must-use plugins and drop-ins, and for a rewrite flush the site's plugins and theme as well. It needs its own permission: the permission to inspect WordPress grants none of it. Each action is a fixed command that Barectl reviews first; there is no command line, flag or script to supply.

Flush rewrite rules
A soft flush that regenerates the stored routes from what WordPress core, the theme and the plugins register, including their own hooks. It never edits Nginx or .htaccess and never hard-flushes.
Flush object cache
Clears only the cache of its own command-line process. WordPress's default object cache lives for one request, so this does not clear the running site's caches, a page cache or a CDN, and is not a live-site cache repair. A site with a cache drop-in is refused.

Preparing a review reads the server and changes nothing. Applying the review is a separate action on its plan page and runs one native unit that outlives this page. Barectl never runs a maintenance action again on its own, even when the outcome of a run is uncertain.
